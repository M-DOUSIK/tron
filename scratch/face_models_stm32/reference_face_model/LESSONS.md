# LESSONS —— 踩坑记录

Grove Vision AI V2（Himax HX6538 + Ethos-U55）人脸识别模型项目全过程的教训汇总。
每条按「现象 → 根因 → 教训」组织。完整技术路线史见 [HISTORY.md](HISTORY.md)。

---

## 1. 压缩投影不等于省 SRAM

**现象**：对 w600k 512D 骨干做 512D→128D 的线性投影 / PCA 降维，PC 侧指标看起来可用，得出"128D 可用"的结论；实际编到 Ethos-U 上 tensor arena 峰值没有任何下降。

**根因**：投影层只是 PC 侧的后处理降维。Ethos-U 的 SRAM 峰值由骨干网络中间张量的最大值决定，末端加一层 512→128 的矩阵乘不改变前面任何一层的激活尺寸。

**教训**：内存预算要看编译器（Vela）报出的 arena 峰值，不能看输出维度。要真正省内存，必须蒸馏 / 训练一个**本身就输出 128D** 的网络。整整一轮 w600k 压缩实验因此对部署毫无意义。

---

## 2. 单数据集调参会系统性伤害另一个数据集

**现象**：只用 LFW 做局部监督调参，出现"LFW 涨、CFP-FP 跌"的跷跷板，反复来回。

**根因**：LFW 以正脸为主，CFP-FP 主打侧脸姿态泛化。单数据集监督会把 embedding 空间往该数据集的分布拉偏。

**教训**：必须同时报两个数据集，并且用**同一个共享阈值**评估。per-dataset 最优阈值表只能用于诊断，不能用于选型——它掩盖了阈值迁移风险，让实际部署时的单一阈值表现远低于表上的数字。

---

## 3. 评估数据管线的隐藏偏差

**现象**：早期 SCRFD 对大量 CFP-FP 侧脸检测失败，有效样本只有 partial 44s/15d；加入 center-crop fallback 后才变成 full 120s/60d。

**根因**：评估管线依赖人脸检测器裁剪，检测失败的样本被静默丢弃。丢掉的恰好是难样本（大姿态侧脸），剩下的是易检测样本。

**教训**：修复前所有 CFP-FP 分数都建立在残缺且偏向易样本的基础上，此前若干轮"CFP-FP 达标"的结论不可信。评估管线必须打印**有效样本数 / 期望样本数**，样本数不满就不能出结论。

---

## 4. 加宽模型不是免费午餐

**现象**：width 1.0 → 1.15，SRAM 599.84 KiB → 702.08 KiB（仍在预算内），但精度断崖式下跌：

| 指标 | width 1.0 | width 1.15 |
|---|---|---|
| LFW TAR@FAR1 | 58.3% | 25.8% |
| CFP-FP TAR@FAR1 | 40.7% | 1.4% |

**根因**：直接复用小模型的训练 recipe（学习率、epoch 数、warmup）去练更宽的骨干，模型没训透就进精调阶段。

**教训**：容量变了，训练配方要跟着变。不同参数量级需要不同的 lr / schedule / 训练时长，不能沿用。

---

## 5. 小样本身份监督帮倒忙

**现象**：给训练加 ArcFace head，训练 loss 正常下降，但下游 LFW / CFP-FP 指标全面下滑。换到 Glint360K 后仍不稳定。

**根因**：LFW+CFP 自带身份标签只有 1046 类，且多数类只有 2–3 张图。这种规模下 ArcFace 的类中心估计噪声极大，监督信号与目标度量脱节——loss 降的是拟合这 1046 个噪声中心。

**教训**：身份监督的价值取决于标签规模和质量，不是"加了就更好"。加辅助 loss 后要看下游指标，不能看训练 loss 曲线。

---

## 6. 数据管线的隐性 bug（两个）

### (a) 常量张量吃内存

**现象**：Glint360K 5 万张图训练时，生成 2.0 GiB 对齐缓存后 GPU 初始化崩溃。

**根因**：身份图片被直接塞进内存常量张量，全量驻留。

**教训**：改成流式读取才解决。数据规模上一个量级时，先审 dataloader 的驻留策略。

### (b) 数据全空转且不报错

**现象**：balanced 200k 数据集训练"跑通了"，但 `stream_valid=0/200000`。

**根因**：身份目录命名格式（`glint360k_*`）没被解析逻辑正确匹配，所有样本被跳过。

**教训**：这是最危险的一类 bug——**流程跑通、不报错、日志正常，但数据全空**。只能靠主动打印有效样本数发现。任何数据管线都必须在启动时打印并断言 `valid > 0` 以及占比。

## 7. 总结性教训：卡住时换范式，不要继续精调

**现象**：S2 蒸馏路线整条线，单阈值 Score 长期在 0.68–0.815 横跳。十几轮 loss 权重 / 超参精调，没有任何一次带来数量级提升。换成 QAT 直训后直接跃升到 LFW 99.33%。

**根因**：瓶颈在训练范式（浮点蒸馏后 PTQ，量化误差吃掉判别力），不在 loss 权重组合。

**教训**：同一条路线连续多轮精调收益在噪声范围内，说明瓶颈不在被调的那个维度。此时继续调参是纯粹的时间损耗，应该换范式。判断标准：设一个"连续 N 轮无数量级提升就换路线"的止损线。
