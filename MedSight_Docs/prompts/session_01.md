# Session 01 — Board Bring-Up: LED Blink

## Prompt for Antigravity (copy-paste as-is)

```
OBJECTIVE
Configure the fundamental clock tree for the STM32N6570-DK and toggle a user LED to
prove the MCU boots and runs correctly. This is the foundation session for the MedSight
smart pill dispenser project — nothing else exists yet.

BACKGROUND AND CONTEXT
This is a brand-new STM32CubeIDE project for MedSight, an AI-powered smart pill
dispenser targeting the STM32N6570-DK board (Cortex-M55 + Neural-ART NPU), ultimately
migrating to µT-Kernel 3.0 for TRON Programming Contest 2026 compliance. This session
only proves the board boots — no RTOS, no AI, no peripherals beyond one GPIO.

RELEVANT PROJECT FILES AND FOLDERS
- Core/Src/main.c
- Core/Inc/main.h
- The .ioc file for this project (create via STM32CubeMX if not already present,
  targeting STM32N657X0)

REQUIRED INPUTS
- STM32N6570-DK user LED pinout (confirm from the board's schematic/user manual;
  do not guess — if uncertain, add a clearly marked TODO comment and flag it in the
  session doc rather than silently assuming a pin)

EXPECTED OUTPUTS
- A bare-metal firmware image with an infinite loop that toggles a user LED at 1Hz
  using HAL_Delay.

CONSTRAINTS
- Do not initialize any RTOS (FreeRTOS or otherwise) this session.
- Do not touch camera, LCD, SD card, UART, or AI peripherals this session — those are
  later sessions.
- Use simple HAL_Delay() for timing — no timer interrupts yet.

CODING STANDARDS
- MISRA-C compliant where reasonably practical.
- Standard STM32CubeIDE project/folder layout — do not restructure the generated
  project skeleton.

FOLDER STRUCTURE TO FOLLOW
Standard STM32CubeIDE structure (Core/Src, Core/Inc, Drivers/, etc.) as generated by
CubeMX — do not create custom top-level folders this session.

FILES TO CREATE
- None beyond the CubeMX-generated project skeleton.

FILES TO MODIFY
- Core/Src/main.c (add the LED toggle loop)

DOCUMENTATION TO UPDATE
- Create docs/milestones/session_01_notes.md recording: exact LED GPIO pin used, clock
  configuration chosen, and any assumptions made about the board pinout.

VALIDATION AND TESTING REQUIREMENTS
- Project must build with 0 errors and 0 new warnings.
- (Manual, by the human developer) LED visibly blinks at approximately 1Hz once flashed.

COMPLETION CHECKLIST
- [ ] .ioc project configured for STM32N657X0 with correct clock tree
- [ ] GPIO configured for the user LED as output
- [ ] HAL_GPIO_TogglePin implemented in the main while(1) loop with HAL_Delay(500) pacing
- [ ] docs/milestones/session_01_notes.md written

COMMON PITFALLS
- Don't assume a pin from a different STM32N6 board variant — the DK's user LED pin is
  specific to this board's schematic.
- Don't enable extra peripherals in CubeMX "just in case" — keep this session minimal.

DEFINITION OF DONE
Code compiles cleanly. The session notes doc explicitly states which pin and clock
settings were used and why. Nothing beyond LED blink is touched.

SELF-REVIEW BEFORE DECLARING COMPLETE
Confirm no RTOS, camera, UART, or AI code was introduced. Confirm the diff only touches
main.c, main.h, and the .ioc file.
```

## Expected Deliverables
CubeMX `.ioc` file, modified `main.c`, `session_01_notes.md`.

## Manual Verification Steps (you, on hardware)
1. Build in STM32CubeIDE — confirm zero errors/warnings.
2. Flash to the STM32N6570-DK via the on-board ST-LINK.
3. Confirm the user LED blinks at ~1Hz.
4. Power-cycle the board and confirm it blinks again from a cold boot.

## Acceptance Criteria
LED blinks reliably across at least 3 power cycles. No HardFaults.
